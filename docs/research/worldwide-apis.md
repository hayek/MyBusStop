# BusBus — Worldwide transit data sources (phone-direct, free)

Research date: 2026-09-22 (all live calls made 08:27–08:57 UTC that day, from Israel). Research only; no app code. Companion to `transit-apis.md` (Israel) — same rigor and legend.

Question answered: **in which countries can BusBus ship with no backend**, i.e. where a free, per-query HTTPS API (JSON/XML/protobuf, phone-sized) satisfies the `TransitProvider` contract — `searchStops`, `lines(atStop:)`, `routePattern(for:)`, `vehicles(for:)`, `arrivals(for:at:)`, `stopsNearby` — with live bus positions, and whose ToS permit a (possibly paid) consumer app.

Confidence legend: **[V]** verified by a live call or official docs read this session; **[I]** inferred / partially verified; **[U]** could not verify. Fit: **FULL** = every method incl. live vehicle positions per line; **ARRIVALS-ONLY** = realtime ETAs at a stop, no positions; **SCHEDULE-ONLY**; **UNUSABLE** = fails a hard constraint (paid, backend-only, dead, ToS).

Machine-readable companion: `worldwide-apis-endpoints.json` (one entry per recommended provider, example URLs that returned HTTP 200 unless marked `ran:false`).

---

## 1. Executive summary

1. **There is no free aggregator that solves this worldwide.** The one technically excellent keyless aggregator, **Transitous (MOTIS 2)**, publishes stops, lines-at-stop, realtime departures and ordered trip stops for ~100 countries in 0.2–0.5 s with no key — but (a) it carries **no vehicle GPS** (MOTIS ingests GTFS-RT TripUpdates only; `map/trips` is schedule+delay interpolation) and (b) its policy, read verbatim today, says **"commercial use is not allowed"** and requires the client to be open-source. It is rejected for a paid closed-source app; it is a strong option only if BusBus is released free + open-source (or MOTIS is self-hosted later, which is a backend). Navitia's freemium tier was discontinued (Sept 2026, €5,000/yr entry), Transitland is 10k req/month per key (backend-only), Transit app is 1,500 calls/month, HERE needs a card on file and has no positions. Google/Moovit/Citymapper: paid/enterprise.
2. **The world is instead unlocked city-by-city / country-by-country**, and the good news is that **19 FULL-fit sources were verified live and keyless today**, plus 2 more with a sanctioned test/demo key, plus ~17 free-self-serve-key FULL sources documented from official specs. Together they cover: **US** (Boston, NYC, DC, Minneapolis–St Paul, Philadelphia, Seattle; + Chicago, Portland with keys), **Canada** (Toronto), **Norway** (all, Oslo arrivals-only), **Finland** (Turku, Tampere keyless; Helsinki with key + keyless MQTT), **Portugal** (Lisbon metro area), **France** (Rennes), **Poland** (Poznań, Gdańsk/Gdynia/Sopot), **Estonia** (Tallinn), **Lithuania** (Vilnius), **Turkey** (Istanbul), **Great Britain** (nationwide via bustimes.org, unofficial), **Hong Kong** (MTR Bus FULL; KMB/Citybus/GMB/NLB arrivals-only), **Japan** (Tokyo Toei); and with free keys: **Singapore, Taiwan, Australia (NSW, VIC), New Zealand (Wellington, Auckland*), Czechia (Prague*), Hungary (Budapest), Spain (Madrid), Romania (Cluj), Brazil (São Paulo), Uruguay (Montevideo), Sweden (Stockholm*), South Korea (*)**. (* = per-key quota makes an embedded key risky.)
3. **Recommended shipping order** (fewest adapters, most countries, least legal risk): (i) the **OneBusAway family** (one adapter → Seattle, DC busETA, NYC discovery, Tampa/San Diego later) — data model already has `distanceAlongTrip`; (ii) **MBTA V3**; (iii) **Entur** (all of Norway, one GraphQL adapter); (iv) **Carris Metropolitana**; (v) **the "Pikas CSV" family** (one adapter → Tallinn + Vilnius/Kaunas); (vi) **the EFA-rapidJSON family** (one adapter → TfNSW with key, Baden-Württemberg/NRW/Linz arrivals-only); (vii) **SIRI-JSON family** (Tampere, Föli, MTA NYC); (viii) singletons in order of verified quality: Rennes STAR, Poznań, NexTrip, WMATA official, TfL (arrivals), Wiener Linien (arrivals), İETT, Toei, HK.
4. **Top risks**: every keyed provider means a **shared key inside the binary** — quotas that are per key (Auckland 35k/week, Golemio 20 req/8 s, Korea 1,000/day dev, Trafiklab Bronze 30k/month, WMATA 50k/day) will be exhausted by a few hundred users; keyless "internal" APIs (Umo/NextBus, MVG, EFA, bustimes.org, red.cl) can vanish without notice; and several sources give positions but no per-stop ETA (İETT, Toei, bustimes, Gdańsk pattern) so the app must compute ETAs from progress — which it already does for the progress rail.

## 4. Aggregators (multi-country)

### 4.1 Transitous / MOTIS 2 (api.transitous.org) — worldwide — fit: ARRIVALS-ONLY; **policy-blocked for commercial apps** — [V]

- Server: MOTIS **v2.11.3** (`/api/v1/map/initial`), `/api/v1/health` → `{"rt":true,"gbfs":true}`. Both `/api/v1/*` and `/api/v6/*` answer. OpenAPI: `https://raw.githubusercontent.com/motis-project/motis/master/openapi.yaml` (214 KB; `api.transitous.org/openapi.json` is 404). CORS `*`. **HTTP 403 without a User-Agent**; policy requires UA = app name + version + contact.
- Live calls (08:27–08:35Z, all HTTP 200, 0.2–0.45 s):
  - `GET /api/v1/geocode?text=Jernbanetorget&type=STOP&language=en` → `[{type:"STOP", name, id:"no-Entur_NSR:StopPlace:3990", lat, lon, country:"NO", modes:["SUBWAY","TRAM","BUS"]}]` (6.7 KB). Stop ids are `<feed>_<gtfs stop_id>`; `?text=900100003` (a stop code) → `[]` → **no search by public code**.
  - `GET /api/v6/stop?stopId=no-Entur_NSR:StopPlace:3990` → `{place, routes:[{routeId:"no-Entur_RUT:Line:3911", routeShortName:"11N", routeLongName, mode:"BUS", agencyName:"Ruter", routeColor}]}` (10 KB) = **lines at stop**.
  - `GET /api/v6/stoptimes?stopId=…&n=10&radius=100` → `stopTimes[]{place{stopId, scheduledDeparture, departure, cancelled}, routeShortName, headsign, realTime:true, tripId}` (22 KB); Oslo: all 11 entries `realTime:true` with delay applied; Berlin VBB likewise = **realtime arrivals** (filter by routeShortName client-side; `direction` is EARLIER/LATER paging).
  - `GET /api/v6/trip?tripId=20260922_10:27_de-VBB_306187615` → `legs[0]{from, intermediateStops[22]{stopId,name,lat,lon,arrival,scheduledArrival}, to, legGeometry{points,precision}, routeId, directionId, headsign, realTime}` (16 KB) = **ordered pattern per trip**.
  - `GET /api/v6/map/stops?min=59.910,10.745&max=59.915,10.755` → 31 stops (8 KB) = nearby (no lines; needs `/stop` per stop).
  - `GET /api/v6/map/trips?zoom=15&min=…&max=…&startTime=…&endTime=…` → 78 trip *segments* with polylines and delay-adjusted times (180 KB for 1×2 km; 549 KB for 4 km) — **interpolation, not GPS**. The MOTIS spec has no vehicle-position entity at all.
- Realtime coverage inside Transitous (from `feeds/*.json`, `spec:"gtfs-rt"`; 809 RT sources in 62 of 137 region files): strong in **FR (348), JP (123), AU-NSW (86), PL (63), ES (24), US-NY (13), UA (12), RO (11), US-CA (11), AU-VIC (10), LT (10)**; some in AT, BE, BG, CZ, DE, FI, NL, RS, SK, CH, GB, IT, NO, HU, IE, PT, EE, GR, IS, KR, LV, NZ; **none** in DK, SE, LU, HK, SG, TW, MY, TH, ID, MX, CO, BO, AE, and effectively none in LATAM (BR/CL rows are FlixBus only).
- **Policy (transitous.org/api, verbatim, read today)**: "Go ahead if all of these points apply to your project: Your project is open-source · Your project is not commercial · Your project is light on our resources"; "**Commercial Use — Due to data source licences and resource prioritisation, commercial use is not allowed.**"; "We provide the service on a best-effort basis and reserve the right to stop providing it to any consumer at any time"; "Please contact us before … doing many requests (also from different users)"; attribution: link to `https://transitous.org/sources/` + OSM attribution. Staging/`*.motis-project.*` hosts must not be used.
- Verdict: **rejected** for a paid/closed app. Keep as the plan-B "free & open-source edition" provider (ARRIVALS-ONLY + interpolated positions), or self-host MOTIS with the Transitous feed config (backend).
- Quirks (from open-source clients), checked 2026-09-28:
  - Transitous' own nginx config ([public-transport/transitous `ansible/roles/nginx`](https://github.com/public-transport/transitous/tree/HEAD/ansible/roles/nginx)): 403 for an empty User-Agent (unless the request looks like a browser) **and** for generic ones (`node`, `python-requests/x.y.z`, `Python-urllib/x.y`, `python-httpx/x.y.z`); `geocode`, `stoptimes`, `map/stops`, `trip` are the "harmless" zone (1,000 req/min per IP, burst 150, upstream read timeout 10 s); everything else under `/api/` — including **`/api/v6/stop`**, which our nearby search calls up to 8× — is 100 req/min per IP, burst 40; `plan` is 20/min per IP and 300/min per User-Agent. Over the limit → **429**. Our UA `BusBus-iOS/1.0 (+URL)` passes.
  - A trip that calls at two platforms of one station comes back **once per call** from `stoptimes` (default radius = the stop, its children and same-named stops): at Oslo Jernbanetorget bus 74 is listed at `NSR:Quay:122003` 15:28 and `Quay:7202` 15:29; Karlsruhe Hbf tram 50 at `89:1:E1` and `89:1:F`, two minutes apart (verified live). Traewelling dedupes by `tripId`, keeping the call at the requested station ([Traewelling/traewelling `app/DataProviders/Motis.php`](https://github.com/Traewelling/traewelling/blob/HEAD/app/DataProviders/Motis.php)). **Fixed** in `TransitousProvider.arrivals` (one arrival per trip, at the rider's own stop when it calls there). `exactRadius=true&radius=0` would restrict to the one stop id (openapi.yaml), but then a StopPlace id returns nothing.
  - Traewelling treats `could not find timetable location`, `unknown feed id`, `stop_found=false` in an error body as "this stop id is gone for good" (feeds get renamed/removed) — a saved Transitous stop can go stale; not handled by us (the board just errors).
  - ha-departures (HA integration, [alex-jung/ha-departures](https://github.com/alex-jung/ha-departures)) polls `stoptimes` every 60 s, 10 s timeout, retries only 429/5xx; GNOME Maps ([GNOME/gnome-maps `src/motis.js`](https://github.com/GNOME/gnome-maps/blob/HEAD/src/motis.js)) sends `gnome-maps/<version>` and uses `/api/v6/stoptimes` + `/api/v6/plan`. Our 30 s board poll costs one `stoptimes` a stop (15 s shared cache).

## 5. Per-source detail — Europe North (Nordics, Baltics, Benelux, DACH)

### 5.1 Entur — NO — FULL (Oslo ARRIVALS-ONLY) — [V]

## 11. Cross-cutting risks and adapter notes

1. **Shared key in the binary.** Every free-key provider issues one key per developer; App Store users share it. Fine when the quota is per IP or generous (LTA 10M/day, TDX 50 req/s/IP, CTA 100k/day, MBTA 1000/min, TfL 500/min, De Lijn 864k/day); dangerous when tight (Auckland 35k/week, Golemio 20/8 s, Korea 1k/day dev, Trafiklab Bronze 30k/month, WMATA 50k/day, TfNSW 60k/day). Budget: one active user ≈ 3 calls/min while the board is open. Gate those providers behind a remote-config flag so they can be switched off.
2. **Unofficial endpoints** (bustimes.org, Umo retro feed, MVG, EFA web backends, red.cl, İETT SOAP, LA Metro): no SLA/ToS, may add Cloudflare/keys any day. Keep them isolated behind the provider abstraction and ship an ARRIVALS-ONLY fallback where one exists (TfL for London, SL for Stockholm, Wiener Linien, transport.opendata.ch).
3. **Positions without ETAs** (İETT, Toei, bustimes.org, Gdańsk when the 31.8 MB pattern dump is skipped, SEPTA scheduled-only): `Arrival.isRealtime` must be false or derived; the progress rail still works from `vehicles(for:)`.
4. **Fleet-wide vehicle feeds** with no line filter (Carris 203 KB pb, Föli 228 KB, Gdańsk 88 KB, Toei 41 KB, Metlink, Trafiklab, TfNSW per operator): acceptable at 20–30 s only when gzip'd and ≤~250 KB; parse GTFS-RT with SwiftProtobuf and filter by `trip.route_id`.
5. **Geo-fenced hosts**: Warsaw, Kraków, Athens, Wrocław CKAN, Riga, STIB (old portal; the keyless gateway is verified, §5.5), San Diego MTS, Pittsburgh, Milwaukee, Winnipeg, TTC official GTFS-RT, STM, datos.cdmx were unreachable from Israel; they are probably fine from inside the country — re-run the health checks from an EU/US/CA vantage before deciding.
5. **Geo-fenced hosts**: Warsaw, Kraków trams (`www.ttss.krakow.pl`; the bus TTSS answers), Athens, Wrocław CKAN, Riga, STIB, San Diego MTS, Pittsburgh, Milwaukee, Winnipeg, TTC official GTFS-RT, STM, datos.cdmx were unreachable from Israel; they are probably fine from inside the country — re-run the health checks from an EU/US/CA vantage before deciding.
6. **Identifier semantics differ**: public stop codes exist in Israel, Boston, Minneapolis, Toronto, Seattle, Singapore, Seoul, Tallinn (SiriID), Wellington, Vienna (RBL), London (SMS code); they do not in Norway, Hong Kong (KMB 16-hex), Transitous, Carris (numeric ids but no sign code) — `searchStops(query:)` must fall back to name search cleanly.
7. **Transport modes**: most feeds mix bus/tram/metro; filter on mode fields (Entur `transportMode`, MBTA `route_type`, TfL `modes=bus`, HSL MQTT topic `/bus/`) so the picker stays bus-only where the product wants that.
8. **Time zones / formats**: SL and İETT return local times without offsets; Rio stamps local time as `Z`; Tallinn/Vilnius use seconds-of-day; Umo/NexTrip epoch ms/s — normalise in the adapter with the provider's fixed TZ.
9. **Things not verified** (mark [U] in the JSON): every free-key provider's live response shape (LTA, TDX, TfNSW, PTV, Metlink, AT, Golemio, BKK, EMT, Tranzy, SPTrans, Montevideo, Trafiklab, CTA, TriMet, HSL routing, Korea); key-in-app clauses for TfNSW, AT, Metlink, De Lijn, HSL; TTC/Warsaw/Athens hosts; LA Metro realtime by day.
